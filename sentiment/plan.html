xev-sentiment 训练计划

从 Qwen3.5-4B-Base 开始，用我们自己写的代码做 post-training，得到一个中文评论的 sentiment classifier（positive / negative，评论来自酒店、笔记本电脑、书籍三个领域），输出的是 calibrated probability。读出方式借用 Kev 的 pointer head 思路，但不使用 Kev 的任何代码和 weights。

这是实验开始之前、经过 review 的计划，保留原样。执行中的改动和全部结果见 实验报告。

总览：七步，三份数据，四个 review 点

整个计划最重要的一条纪律是三份数据各管各的：train 只用来训练；validation 用来测 baseline、选 checkpoint、拟合 temperature；test 一直锁着，只在 Step 6 读一次。这样最后的 test 结果才没有被我们的选择"偷看"过。

Step 1 · prepare_data.py

Data preparation

数据从哪来

  • Hugging Face 上的副本：lansinuote/ChnSentiCorp 是一个转存版本，只有三个 parquet 文件和一个 dataset_infos.json，没有 README，没有写来源，也没有写 license。
  • 原始语料：ChnSentiCorp 通常指谭松波（中科院计算所）整理的中文情感语料，评论来自酒店、笔记本电脑、书籍三个领域。9,600 / 1,200 / 1,200 这个切分和百度 ERNIE、PaddleNLP 里常用的 ChnSentiCorp 版本一致。
  • 我抽查了 train 里的 600 条（按关键词粗分，只是估计）：酒店约 29%，书籍约 27%，笔记本电脑约 26%，分不出来约 15%，同时提到几个领域约 3%。正负 298 : 302，基本平衡。
  • 里面的情况：有繁体字评论；也有不少评论讲的是商城（比如当当）的发货和降价，而不是商品本身。
  • License：没有写明，按惯例只用于研究和学习。数据不会提交、也不会再分发（data/ 已在 .gitignore 里）。

因为不只是酒店评论，题目措辞已从"这条酒店评论的情感倾向是？"改成"这条评论的情感倾向是？"。

目的
拿到干净、没有 leakage 的三份数据，并知道评论有多长。
输入 → 输出
ChnSentiCorp@b0c4c119→data/train.jsonlvalidation.jsonltest.jsonlstats.json
做法
  • 按固定 revision 下载；每行写成 {"id", "text", "label"}，label 用 "negative" / "positive"。
  • 去掉空文本和同一份数据里的重复评论。
  • Leakage check：validation 或 test 里如果出现和 train 一模一样的评论，就删掉，否则 test 分数会虚高。
  • 统计 label balance，以及长度的 p50 / p90 / p99 / max（按字符和 Qwen token 两种算）。
  • 按关键词粗分三个领域，统计每个领域的数量和正负比例，后面 error analysis 也按领域分开看。
验收
三个文件写出；没有 train 与 test 的重叠；拿到 token 长度分布，用来定 MAX_TEXT_TOKENS。
Review
R1：我把统计结果和每类 3 条样例发给你，一起决定截断长度（草稿是 384 token，超长时保留开头一半和结尾一半，因为结论常在最后）。
Step 2 · baseline.py

Zero-shot baseline

目的
知道"什么都不训练"时 base model 能做到多少，后面才能说清楚 post-training 带来了多少。
做法
  • 保留 LM head，用 prompt：评论：…\n这条评论的情感是？\nA. 正面\nB. 负面\n答案：
  • 只看下一个 token 是 "A" 还是 "B" 的 logit，softmax 成两个概率。
  • A/B 两种顺序都跑一遍，量出 base model 自己的 option-order bias。
  • 只在 validation 上跑；它的 test 数字留到 Step 6 和我们的模型一起读。
验收
得到 validation 上的 accuracy、NLL、ECE，以及交换顺序后的 flip rate。
Step 3 · model.py

Model

模型由三块组成：冻结的 backbone、可训练的 LoRA、从零开始训练的 pointer head。每条评论只有一道题，所以不需要 Kev 那种题与题之间的 attention mask，普通的从左到右 forward 就够了。

Input format
<state> 评论 <q> 这条评论的情感倾向是？ <opt> 负面：不满意、抱怨、批评 </opt> <opt> 正面：满意、称赞、推荐 </opt> <decide>。5 个分隔符借用 Qwen 词表里的 <|fim_prefix|>、<|fim_middle|>、<|box_start|>、<|box_end|>、<|fim_suffix|>。用户文本里的 <|…|> 会先被改写，防止伪造分隔符。
Backbone
AutoModelForCausalLM.from_pretrained(...).model，即去掉 LM head 的 Transformer 本体，bf16，参数 frozen。
LoRA
r = 16，alpha = 32，dropout = 0.05。target modules：attention 的 q/k/v/o_proj，MLP 的 gate/up/down_proj，Gated DeltaNet 的 in_proj_qkv/z/a/b 和 out_proj。LoRA weights 用 fp32。
Pointer head
W_q、W_k 都是 d → 256 的 linear layer，随机初始化，fp32。score = q·k / √256。
Padding
Right padding。pad 都在真实 token 之后，从左到右的模型看不到它们，对 attention 层和 DeltaNet 层都安全。
验收
一个 batch 的 forward 输出形状是 [B, 2]；打印 trainable parameters 数量；确认 checkpoint 里只加载了 text 部分（这个 base checkpoint 可能带 vision weights）。
Step 4 · train.py

Training

每个 optimizer step 的流程如下。重点是第 ② 步：每条样本每个 epoch 都随机决定两个选项的顺序，否则 pointer head 可能学会"永远选第二个"这种 shortcut。

Smoke run
先只用 200 条样本跑约 20 个 step：确认能放进显存、loss 在下降、速度多少。第一次运行时 DeltaNet 的 kernel 要编译，会多花几分钟。
Logging
每 20 步记录 loss、running accuracy、learning rate、tokens/s、GPU memory，写进 runs/<name>/train_log.jsonl。
Checkpoint
LoRA adapter（save_pretrained）+ head.pt（pointer head weights、temperature、配置、数据文件 hash）。
验收
validation loss 下降并趋于平稳；没有明显 overfitting（train 和 validation 的差距不再变大）；最优 checkpoint 已保存。
Review
R2：smoke run 之后给你看显存、速度和预计总时长，确认后再跑完整训练。R3：完整训练结束后给你看 loss 曲线和 validation 指标，再进入 calibration。
Step 5 · calibrate.py

Calibration（temperature scaling）

目的
让模型说"90% 把握"时，确实有大约 90% 答对。
做法
  • 用最优 checkpoint 在 validation 上跑一遍，记录 T = 1 时的原始 logits。
  • 在 0.25 到 4 之间取 121 个对数均匀的 T，找让平均 NLL 最小的那个，写进 head.pt。
  • T 对两个 logits 同比例缩放，argmax 不变，所以 accuracy 不变，只有 confidence 变。
验收
报告 calibration 前后 validation 上的 ECE 和 NLL。

指标含义
accuracy答对的比例
NLL正确答案概率的 −log 平均值，也就是训练用的 loss，越小越好
Brier score概率和真实答案（0 或 1）的平方差，越小越好
ECE按 confidence 分 10 个桶，看"说的把握"和"实际准确率"差多少
confident error概率 ≥ 0.9 却答错的比例
coverage @5% / @1%只自动处理最有把握的那部分评论，在错误率不超过 5%（或 1%）时，最多能自动处理多少
order flip把两个选项交换顺序后，答案变了的比例
统计显著性
对"ours vs baseline"的 accuracy 差做 paired bootstrap（1,000 次重采样），给出 95% confidence interval。1,200 条 test 在 94% 左右时，sampling error 约 ±1.3 个百分点。
Error analysis
列出最有把握却答错的 20 条，逐条看原因：label 噪声、反讽、褒贬混合，还是模型真的理解错了。
参考
公开结果里 BERT 一类模型在 ChnSentiCorp 上大约 94–95%。

Serving

→ 200
